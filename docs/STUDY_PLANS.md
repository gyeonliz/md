# 병행 학습 계획

기준일: 2026-08-25 (Asia/Seoul)

## 1. 운영 기준

정보처리산업기사와 C++ 코딩테스트는 Unreal/Git 환경 및 드론 프로젝트와 병행한다. 학습 때문에 드론 프로젝트 시간이 지나치게 줄지 않도록 하며, 두 학습 영역의 기록은 프로젝트 작업과 분리한다.

- 정보처리산업기사: `개념 → 문제 → 오답`
- C++ 코딩테스트: 코딩테스트를 하는 날 1문제, 여유가 있으면 최대 2문제를 기본으로 함
- 정보처리산업기사 2026년 공식 회차 일정은 확인 완료
- 사용자의 3회 접수 여부, 수험표상 필기일, 기존 필기 합격·면제 상태는 현재 미정
- 개인 수험일이 확인되면 정보처리산업기사 계획을 해당 D-Day 기준으로 압축
- 이 문서에는 확인되지 않은 시험 일정이나 세부 출제 범위를 임의로 넣지 않음

날짜별 실행안과 현재 Drone 상태를 한 번에 볼 때는 [`MOBILE_CURRENT_BRIEF.md`](MOBILE_CURRENT_BRIEF.md)를 먼저 읽는다.

## 3. 정보처리산업기사 계획

### 기본 학습 루프

1. 학습할 개념을 정한다.
2. 개념을 공부한다.
3. 관련 문제를 직접 푼다.
4. 틀린 문제의 원인을 분류한다.
5. 부족한 개념 또는 암기를 보완한다.
6. 같은 문제를 다시 풀어 이해 여부를 확인한다.

### 오답 원인 분류

| 분류 | 판단 기준 | 다음 행동 |
|---|---|---|
| 개념 부족 | 개념 자체를 설명하기 어려움 | 해당 개념으로 돌아가 다시 정리 |
| 암기 부족 | 이해했지만 용어·정의·내용이 기억나지 않음 | 암기 항목으로 분리하고 반복 확인 |
| 개념 혼동 | 비슷한 개념을 서로 바꿈 | 두 개념의 차이를 나란히 비교 |
| 계산 실수 | 풀이 방향은 맞지만 계산 과정에서 틀림 | 계산 과정을 다시 쓰고 실수 지점 표시 |

한 문제에 원인이 여러 개라면 주된 원인 하나와 보조 원인을 함께 기록할 수 있다. 단순히 `틀림`으로 끝내지 않는다.

### 학습 기록 양식

```text
날짜:
학습한 개념:
푼 문제:
맞음/틀림:
오답 원인: 개념 부족 | 암기 부족 | 개념 혼동 | 계산 실수
보완한 내용:
재확인 결과:
다음 학습:
```

### 개인 수험일·접수 상태 확인 전 운영

- 개념, 문제, 오답의 세 단계가 매 학습 기록에 남도록 한다.
- Track A/B/C를 정하기 전에는 특정 시험일까지의 진도율을 임의로 정하지 않는다.
- 취약점은 오답 원인별 누적으로 확인한다.
- 수험표의 실제 시험 날짜가 확인되기 전에는 D-Day를 확정본으로 만들지 않는다.

### 시험 날짜 확정 후 작성할 D-Day 계획 틀

```text
시험 날짜:
D-Day:
남은 학습 범위:
누적 오답:
개념 부족 항목:
암기 부족 항목:
개념 혼동 항목:
계산 실수 항목:
기간별 목표:
최종 점검 계획:
```

수험표 날짜가 알려지면 남은 기간과 실제 학습 상태를 기준으로 [`MOBILE_CURRENT_BRIEF.md`](MOBILE_CURRENT_BRIEF.md)의 해당 Track을 압축하거나 확장한다.

## 4. C++ 코딩테스트 계획

### 학습 단계

#### 1단계: C++ 기본

- 입출력
- 조건문
- 반복문
- 배열
- 문자열
- 함수

#### 2단계: STL과 기본 자료구조

- `vector`
- `sort`
- `stack`
- `queue`
- `deque`
- `map`
- `unordered_map`
- `set`
- `priority_queue`

#### 3단계: 알고리즘

- DFS
- BFS
- 재귀
- 그래프
- 이분탐색
- Greedy
- DP

각 단계의 정확한 종료 날짜는 현재 정하지 않는다. 문제 풀이 기록에서 부족한 부분을 확인한 뒤 다음 단계로 이동한다.

### 문제 풀이 루프

```text
문제 확인
→ 직접 풀이
→ 실패
→ 실패 이유 확인
→ 정답 아이디어 공부
→ 다시 직접 구현
→ 며칠 뒤 재풀이
```

정답 아이디어를 본 뒤에는 코드를 그대로 옮기는 것으로 끝내지 않고 다시 직접 구현한다. 재풀이 날짜는 첫 풀이 기록에 남긴다.

### 코딩테스트를 하는 날의 기본 단위

- 1문제를 기본으로 하고 시간이 남으면 최대 2문제
- 주당 실행 횟수는 사용자 가능 시간 확인 전까지 이동용 문서의 임시 최소안을 사용
- 각 문제에서 먼저 직접 풀이 시도
- 실패했다면 실패 이유를 한 문장 이상 기록
- 정답 아이디어를 공부한 뒤 다시 직접 구현
- 재풀이할 문제를 별도 목록에 추가

프로젝트 작업과 충돌하는 날에는 기본 범위 안에서 1문제를 선택하고, 문제 수를 늘려 Unreal 프로젝트 시간을 잠식하지 않는다.

### 문제 기록 양식

```text
날짜:
문제:
단계/주제:
첫 접근:
결과: 성공 | 실패
실패 이유:
공부한 정답 아이디어:
다시 구현한 결과:
재풀이 예정:
재풀이 결과:
```

### 단계 이동 점검

다음 단계로 넘어가기 전에 날짜나 문제 수만 보지 않고 아래를 확인한다.

- 현재 주제의 문제에서 직접 풀이를 시도할 수 있는가
- 실패 이유를 구체적으로 설명할 수 있는가
- 아이디어를 공부한 뒤 스스로 다시 구현할 수 있는가
- 재풀이에서 같은 이유로 반복해서 막히는 항목이 무엇인가

반복해서 막히는 항목은 현재 단계의 Todo로 남기고 보완한다.

## 5. 병행 관리 방식

두 학습 영역은 프로젝트 보드에서 각각 `정보처리산업기사`, `Coding Test`로 구분한다.

### 정보처리산업기사 카드 예시

- `[정보처리산업기사] 개념 학습 기록 작성`
- `[정보처리산업기사] 관련 문제 풀이`
- `[정보처리산업기사] 오답 원인 분류 및 보완`
- `[정보처리산업기사] 시험 날짜 확정 후 D-Day 계획 작성`

### 코딩테스트 카드 예시

- `[Coding Test] C++ 기본 문제 1~2개 직접 풀이`
- `[Coding Test] 실패 이유와 정답 아이디어 기록`
- `[Coding Test] 이전 실패 문제 재풀이`
- `[Coding Test] 다음 학습 단계 이동 여부 점검`

- [ ] 오늘 1~2문제 범위에서 직접 풀이했는가
- [ ] 실패 이유를 기록했는가
