# 사용자 공통 작업 규칙 (정규연)

원본: Codex가 2026-10-01 정리한 "Claude 전달용 사용자 작업 규칙"(이전 대화·드론 AGENTS.md 근거). 모든 과거 대화·개인 설정을 다 조회한 목록은 아니다.
md 저장소 `docs/git/USER_RULES.md`가 **공유 원본**이며, 각 PC `~/.claude/CLAUDE.md`가 이를 가져온다(Unreal 저장소 `.claude/codex-bridge/Test-CollabSetup.ps1 -InstallUserRules`).
프로젝트 전용 규칙(드론 등)은 각 저장소의 `CLAUDE.md`·`AGENTS.md`에 있다.

## 공통 작업 원칙

1. **정확성 우선.** 추측을 사실로 만들지 않는다. 확정된 내용·현재 구현·제안·미정·미구현을 구분한다. 사용자가 확정하지 않은 설정이나 기능을 임의로 확정하지 않는다. 사용자가 "알아서 정해 달라"고 위임한 부분은 결정하되, 채택한 기본값과 근거를 설명한다.
2. **가능한 작업은 직접 진행한다.** "진행해", "쭉 해줘", "남은 것도 해줘"는 실제 작업 지시다. 할 수 있는 구현·연결·설정·정리를 사용자에게 떠넘기지 않는다. 중단된 작업은 현재 상태를 확인하고 이어간다. 검토할 만한 완성도를 갖춘 뒤 보고한다.
3. **사용량과 시간을 아낀다.** 필요한 자료와 관련 부분부터 본다. 같은 자료를 반복해 읽거나 근거 없이 검사를 반복하지 않는다. 단, 요청한 작업의 완성도와 필요한 검증은 확보한다.
4. **실제 결과를 검증한다.** 코드·로그뿐 아니라 기능이 연결된 실제 화면·맵·입력·동작을 확인한다. 테스트 대상과 연결 상태를 확인해 엉뚱한 맵에서 검사하지 않는다. 자동 검사 통과와 수동 확인 완료를 구분하고, 미확인 항목을 완료로 보고하지 않는다.
5. **상태와 다음 작업을 문서로 남긴다.** 현재 구조, 완료한 작업, 남은 문제, 다음 작업, 사용자가 해야 할 일, 테스트 방법을 구분한다. 보고에는 잘 되는 것과 안 되는 것을 함께 적는다.
6. **Git은 최신 요청을 따른다.** 별도 지시 없이 자동 커밋하지 않는다. 커밋을 요청받으면 메시지는 읽기 쉬운 한국어로 쓴다. 다른 프로젝트에서는 그 작업의 명시적 Git 요청을 따른다.
7. **다른 PC나 에이전트가 바로 이어갈 수 있게 정리한다.** 프로젝트 파일(Git/GitHub)과 대화·작업 문맥(전달 문서)을 구분한다. 이어갈 작업, 경로, 설정, 실행·검증 방법을 기록한다. 인증 정보·비밀번호는 복사하지 않는다.
8. 한국어로 답한다.

## Unreal 개발과 학습

- 기능 단위로 구현·테스트한 뒤 다음 단계로 넘어간다. MVP와 짧아도 완결된 플레이 사이클을 우선한다.
- 새 시스템 설명 순서: 필요한 이유 → 담당 클래스 → 헤더 변경 → CPP 변경 → Blueprint 설정 → Editor 테스트 → 정상 결과 → 문제 확인 항목.
- 이미 경험한 기초는 매번 장황하게 설명하지 않는다. 새 구조와 연결 설정은 명확히 설명한다.
- 구현한 기능을 직접 시험할 수 있게 테스트 맵과 사용 가이드를 구성한다.
- 실제 플레이 흐름, UI 상호작용, 패드 입력, 뒤로가기, 성능·최적화까지 확인한다.

## 이미지·스프라이트

- **원본 그림체와 비율 유지가 1순위다.** (2026-07-18 "항상 박아둬")
- 기존 idle과 새 모션의 그림체·크기·신체 비율을 맞추고 동작이 자연스럽게 이어지게 한다.
- 발바닥 위치와 중심점을 일관되게 맞춘다. 여백을 충분히 둬 발·칼끝·무기·이펙트가 잘리지 않게 한다.
- 비정상적인 인체 구조, 무기 복제, 어색한 반복, 걷기 중 미끄러짐을 직접 보고 검증한다.

## 세계관·기획

- 기존 사용자 설정을 먼저 읽고 연결한다. 새 설정이나 이름은 제안임을 구분한다.
- 도시·NPC·동선·퀘스트·전투·스토리의 관계와 배치 이유를 설명한다.
- 전체 지도와 도시별 그림의 그림체를 통일하고, 필요하면 노드 시각화로 관계를 보여준다.
- 드론 프로젝트의 J3C는 가상의 발주처다. 실제 계약·협력·지원 관계로 표현하지 않는다.
