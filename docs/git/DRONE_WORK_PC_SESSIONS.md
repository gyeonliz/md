# 작업컴 드론 세션 분리·시작 가이드

기준: 2026-10-22. **작업컴에서 새로 열 대화의 구성과 복사할 첫 지시문**이다. 현재 PC의 대화 ID·절대 경로를 작업컴에 그대로 사용하지 않는다. 이 문서 작성으로 새 세션 생성이나 구현을 시작한 것은 아니다.

## 1. 작업컴에서 먼저 할 일

1. 사용자가 메인컴 변경을 커밋·푸시한 뒤 작업컴의 MD/Unreal 저장소를 갱신한다. 작업컴 미커밋 변경이 있으면 먼저 보존하고 충돌을 해결한다. 실제 HEAD와 작업 트리를 확인한다.
2. 아래 `<MD_ROOT>`와 `<DRONE_ROOT>`를 작업컴 실제 경로로 정한다. C PC의 `C:/URproject/drone`이나 `E:/기획안`이 존재한다고 가정하지 않는다.
3. MD의 `STATUS.md`, `WORKBOARD.md`, [현실 조종감 계획](../gameplay/DRONE_REALISTIC_HANDLING_PLAN.md)만 먼저 읽고 필요한 상세 문서를 연다. 게임 저장소의 AGENTS/CLAUDE도 관련 부분을 읽는다.
4. 아래 총괄 대화부터 열고 나머지 역할을 연결한다. 작업컴에서 생성된 새 대화 ID와 소유 파일을 기록한다. 옛 Claude local ID나 메인컴 ID를 복사하지 않는다.

메인컴 실행 증거·원본 사진·스크립트는 Git에 모두 포함됐다고 가정하지 않는다. 파일이 없으면 최신 MD의 보고 결과와 작업컴 직접 검증을 구분하고, 필요한 비밀값 없는 산출물만 별도로 전달받는다. 인증 파일·토큰·로그인 상태는 이관하지 않는다.

새 구현을 여러 세션에서 한꺼번에 시작하는 구성이 아니다. 물리 조사·UI 읽기 조사·문서 검토는 병렬로 하고, 맵 실행·빌드·Content 변경은 한 줄로 진행한다. 사용량이 부족하면 검증·MD 역할을 총괄에 합쳐 4개로 운영한다.

## 3. 우선순위와 작업 계약

- 최우선 제품 목표: 실제 드론 조종자가 이질감을 거의 느끼지 않는 물리·조종감. Racer는 레이싱용, 기타 공중 기체는 전쟁에서 사용되는 역할별 기체를 참조한다. UGV는 지상 모델이다. 특정 모델/정확 사양·제어 모드·조종기·숙련자 평가 여부는 미정이다.
- 물리는 우선 조사·개선안 제출 단계다. 단순 B안 채택은 보류됐으며 확장 B/Chaos C를 근거·접촉 요구·비용으로 비교한다. 바로 전 기체 수치를 바꾸지 않는다.
- 구현·시험 계획: M3/4 목표/오브젝트 연결, 미션 렉·로딩 계측, 쓰로틀 OFF·정상 착지·재이륙, 화면 상하 시야/감도, LOS 사람 후퇴와 드론을 향한 메시·카메라 방향. 각각 완료 기준을 따로 둔다.
- 물리와 카메라가 공유하는 FlightPawn, Definition, IMC/BP를 동시에 수정하지 않는다. 먼저 `파일 / 작성 역할 / 읽기 역할 / 인계 조건`을 총괄에 등록한다. UI 역할은 축·명령 계약을 전달하고 공유 입력 코드는 지정 소유자가 적용한다.
- 모든 엔진 실행은 실행 담당에게 요청한다. 물리/UI 역할은 패치·파일 SHA·검사명·예상 결과를 전달한다. 빌드/실행 중 소스를 바꾸지 않는다. 사용자가 켠 Editor를 임의 종료하지 않는다.
- 작업컴 성능은 별도로 확인한다. C PC의 과거 메모리 실패나 시작 기준을 작업컴 실측 결과로 쓰지 않는다. 보호 기준은 이유와 함께 정하고 부족할 때 반복 실행/다른 앱 강제 종료로 해결하지 않는다.
- START와 BACK은 영문 유지. 팀원 원본 UI/폰트/Production Training을 보존한다. 개인 랜덤도시는 팀 공유 보고서에서 제외한다. 로딩 비교가 필요하면 별도 개인 시험으로 구분한다.

## 4. 대화별 첫 메시지 — 그대로 복사

각 메시지의 `<MD_ROOT>`, `<DRONE_ROOT>`, `<WORK_PC_LEAD_ID>`를 실제 값으로 바꾼다. 총괄로 결과 전송은 사용자가 아래 지시문을 해당 대화에 직접 넣어 승인하는 방식이다.

### 총괄

```text
작업컴 드론 총괄이다. MD=<MD_ROOT>, Unreal=<DRONE_ROOT>.
각 저장소 지침과 STATUS/WORKBOARD, docs/git/DRONE_WORK_PC_SESSIONS.md를 필요한 부분만 읽고 실제 경로/HEAD/변경을 확인해라. 과거 작업을 자동 재개하지 말고 현재 분담과 물리 조사 우선 지시를 기준으로 진행해라.
물리·본미션/LOS/성능 실행·카메라/UI·검증/MD 대화의 작업컴 ID와 파일 소유권을 관리해라. 엔진/빌드/Content 작성자는 실행 담당 하나로 유지한다. 공유 FlightPawn/입력 파일의 중복 수정을 막아라.
담당 보고를 받아 구현/자동검증/실화면/실물패드를 구분해서 짧게 알려줘. 커밋/푸시는 하지 말고 변경 내역과 한국어 커밋 초안을 준비해라.
```

### 비행 물리·착지 조사

```text
작업컴 드론 물리 조사 담당이다. MD=<MD_ROOT>, Unreal=<DRONE_ROOT>, 총괄=<WORK_PC_LEAD_ID>.
docs/gameplay/DRONE_REALISTIC_HANDLING_PLAN.md와 실제 비행 코드를 대조해라. 최우선은 숙련 실조종자가 이질감을 거의 느끼지 않는 조종감이다. Racer는 레이싱용, 기타 공중 기체는 역할별 전쟁 사용 기체, UGV는 별도다.
현재는 조사·개선안 단계다. 추력/중력/관성/항력/모터 응답/입력/Rates/스로틀/접지와 정상 재이륙을 조사하고 확장 B/Chaos C의 근거·한계·단계별 검증안을 제시해라. 새 물리/수치/자산 구현을 먼저 시작하지 마라. 조종기와 기준 기체의 미정 조건을 추측하지 마라.
엔진은 직접 켜지 말고 실행 담당에 필요한 검사를 총괄 경유 요청해라. 결과·막힘을 위 총괄 대화로 보내는 것을 사용자가 승인한다. 원인/제안/미확인을 구분해 보고해라.
```

### 본미션·LOS·성능 실행

```text
작업컴 드론 본미션/LOS/성능 실행 담당이다. MD=<MD_ROOT>, Unreal=<DRONE_ROOT>, 총괄=<WORK_PC_LEAD_ID>.
현재 문서와 실제 맵/소스부터 대조해라. M3/4 오브젝트와 목표 연결, 미완료 사진/실출격, LOS 사람을 뒤로 이동하고 드론을 바라보게 메시 Yaw/카메라 방향 조정, 미션 렉/긴 로딩 계측이 담당 범위다. 사용자 맵·설정에서 증거를 남겨라.
엔진/PIE/빌드/Content 변경은 이 세션만 담당한다. 다른 역할의 소스가 준비된 후 변경 목록을 고정해 빌드한다. 공유 FlightPawn/입력/물리 파일을 임의 변경하지 말고 총괄과 소유권을 먼저 맞춰라. 새 물리 구현은 현재 조사 우선이므로 시작하지 마라.
기존 변경/원본/시작ID를 보존하고 실제 작업컴 자원 조건을 확인해라. 패키징/전체 쿠킹 등 10분 넘는 작업은 먼저 영향과 시점을 확인해라. START/BACK 영문 유지, 자동 커밋/푸시 없음.
단계 결과·막힘을 위 총괄로 보내는 것을 사용자가 승인한다. 실행 로그·새 화면·미검증을 구분하고 전체 완료로 뭉뚱그리지 마라.
```

### 카메라·설정 UI

```text
작업컴 드론 카메라/설정 UI 담당이다. MD=<MD_ROOT>, Unreal=<DRONE_ROOT>, 총괄=<WORK_PC_LEAD_ID>.
화면 상하 시야(카메라 피치)는 기체 상승/하강과 구분한다. 패드 기본/게임 조작의 낮은 회전감도와 상하 불가를 실제 원시축→IA→모드→SpringArm/ViewTarget 경로로 조사하고 감도XY/반전/적용·취소·기본값·저장 연결안을 작성해라.
현재 일반 Pitch 코드는 있으므로 코드 없음으로 단정하지 마라. 기체 Yaw와 자유 카메라 회전을 구별해라. FlightPawn/Definition/IMC/BP는 물리/실행 역할과 겹치므로 단독 수정하지 말고 파일 계약부터 총괄에 제시해라. UI/설정의 구현은 범위 계약 이후 기능단위로 진행한다.
START/BACK 영문과 팀원 UI 가이드를 보존해라. 엔진/Content 변경은 실행 담당에게 맡겨라. 결과·막힘을 위 총괄로 보내는 것을 사용자가 승인한다. 자동 커밋/푸시 없음.
```

### 검증·MD

```text
작업컴 드론 검증/MD 담당이다. MD=<MD_ROOT>, Unreal=<DRONE_ROOT>, 총괄=<WORK_PC_LEAD_ID>.
실제 diff·로그·캡처와 최신 계획을 대조해 STATUS/WORKBOARD/관련 가이드의 현재 절만 갱신해라. 같은 사실은 정본 하나와 링크로 관리하고 이전 기록을 보존해라. 다른 역할의 게임 소스/자산/엔진은 변경하지 마라.
현실 물리는 조사/계획이지 구현 완료가 아니다. 메인컴 결과와 작업컴 직접 검증, 자동 검사와 실화면/실물 패드를 구분해라. 개인 랜덤도시는 팀 공유 보고에서 제외한다.
변경 파일/링크/git diff --check를 확인하고 한국어 커밋 제목·본문 초안을 준비해라. stage/commit/push는 하지 마라. 결과·막힘을 위 총괄로 보내는 것을 사용자가 승인한다.
```

## 5. 보고·인계 형식

각 역할은 자기 작업 경로에 최신 상태 하나를 두고 아래만 적는다. 총괄은 실제 새 대화 ID와 이 상태 경로를 한 표로 관리한다.

```text
역할 / 실제 작업컴 경로 / HEAD:
소유 파일 / 현재 엔진 소유자:
완료: 구현 / 자동검증 / 실화면 / 실물 조종 구분
근거: 로그·화면·변경 파일 경로, 설정·맵·입력 조건
미완료·막힘과 필요한 선행 작업:
다음 작업 / 다른 역할에 넘길 계약:
```

처음부터 모든 과거 대화를 가져오지 않는다. 최신 공유 MD와 실제 파일을 우선하고, 없는 근거가 필요할 때만 원본을 찾는다. 다른 세션에 메시지는 사용자의 현재 전송 지시 범위에서만 보낸다. 총괄 보고 지시가 다른 모든 대화에 임의 전송할 권한을 뜻하지 않는다.
